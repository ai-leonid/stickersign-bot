# Интеграция с Telegram

## Подход
- Для старта используется long polling, webhook - не нужен
- Централизация работы с Telegram API в одном адаптере
- Библиотека grammy для обработки апдейтов

## Режим запуска
- Long polling упрощает локальную разработку и не требует публичного URL (Webhook - не нужен)

## Адаптер Telegram API и точки интеграции
- BotModule принимает апдейты, валидирует вход и маршрутизирует команды
- PackManagerService напрямую вызывает Telegram Bot API через HTTP
- Генератор стикеров готовит WebP-буферы для загрузки

## Команды и ответы бота
- /start — краткая инструкция и пример фразы
- /create <фраза> — создать новый набор
- /update <фраза> — пересоздать первые 25 стикеров
- /button — запросить загрузку пользовательской картинки
- Ответы: подтверждение принятия, статус генерации, ссылка на набор
- Картинка для /button отправляется как файл PNG/WebP с прозрачностью

## Операции со стикерпаком
- createNewStickerSet для создания нового набора
- replaceStickerInSet для замены первых стикеров
- addStickerToSet для добавления недостающих
- getStickerSet для чтения текущего состава
- Проверка лимита 120 статических стикеров
- Загрузка WebP через multipart/form-data с attach://

## Ограничения, которые учитываются
- Сетка 5x5 отображает первые 25 стикеров
- Требования к формату изображений, размеру и прозрачности
- Необходимость заполнения пустых ячеек

## Обработка ошибок
- Ретраи при сетевых сбоях и 5xx с экспоненциальной паузой
- 429: уважать retry_after и повторять запрос
- 400: вернуть понятное сообщение пользователю без ретраев
- 401/403: остановить обработку и сигнализировать о проблеме конфигурации
- Деградация на текстовый ответ при ошибках генерации
- Протоколирование ошибок с сохранением контекста запроса
